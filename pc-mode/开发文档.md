# 手机当主机 · PC 模式 开发文档

> 版本：v2（2026-10-31）
> 目标：把 Redmi K70 Pro 当主机用，PC 只负责屏幕、键盘、鼠标。
> 结论：**Android 侧只能做到"多窗口"，真正的 PC 桌面靠手机里的 XFCE（Linux）；两层并存，可秒切。**

---

## 1. 架构一览

```
┌──────────────────────── Windows PC (2880x1800 @200%) ────────────────────────┐
│  scrcpy 5.0.1 窗口（无边框，2880x1800 物理像素 = 整屏）                       │
│       ▲ USB 40Mbps / uhid 键鼠直通                                            │
└───────┼───────────────────────────────────────────────────────────────────────┘
        │
┌───────┴──────────────────── 手机 (HyperOS 3 / Android 16) ───────────────────┐
│  虚拟屏 displayId=N  (scrcpy --new-display=2880x1800/396)                     │
│    ├── [层一] Android 应用：freeform 小窗 / --windowingMode 1 全屏            │
│    └── [层二] Termux:X11 全屏 → XFCE 4.20 桌面（真窗口管理器 xfwm4）          │
│  手机本机屏幕：完全不受影响，照常打电话刷微信                                  │
└──────────────────────────────────────────────────────────────────────────────┘
```

两层是**同一个虚拟屏上的两个全屏任务**，互相切换；手机本机屏幕（displayId 0）从不参与。

## 3. 两层方案

### 层一：Android 虚拟屏（scrcpy）

```bat
2-start-pc.bat
```
- 内核命令：`scrcpy -d --new-display=2880x1800/396 --start-app=com.android.chrome --window-borderless --window-x 0 --window-y 0 --window-width 2880 --window-height 1800 --max-fps 60 --video-bit-rate 40M --keyboard=uhid --mouse=uhid`
- 虚拟屏分辨率 = PC 面板物理像素，1:1 无缩放，最清晰
- `396dpi` ≈ 1163×727dp 的桌面空间
- 必须带 `--start-app`：**空虚拟屏会被系统回收**
- 键鼠用 `uhid`（内核 HID），**不需要** "USB 调试（安全设置）" 权限

启动后可对安卓应用做：
| 脚本 | 作用 |
|---|---|
| `2-app-full.bat <包名>` | 在该虚拟屏上**全屏**打开应用（`--windowingMode 1`），布局会按 1163×727dp 重排 |
| `open-app.ps1 <包名> [-Windowed]` | 同上，`-Windowed` = freeform 小窗 |
| `4-windows.bat` / `pc-win.ps1 list\|max\|tile\|reset` | 小窗管理：列窗口 / 平铺 / 最大化 / 还原 |

**层一的天花板**：freeform 小窗被 MIUI 限制在画布约 70%，没有标题栏、不能贴边吸附，鼠标拖不动——所以需要层二。

### 层二：Linux 桌面（Termux + termux-x11 + XFCE）

```bat
5-xfce.bat        :: 启动/重启桌面
to-desktop.bat    :: 从安卓应用切回桌面（不重启）
stop-xfce.bat     :: 只停桌面
```

手机侧已安装：

| 组件 | 版本 / 说明 |
|---|---|
| Termux | 0.118.3 GitHub **debug** 构建（debuggable → PC 可用 `run-as` 直接驱动） |
| Termux:X11 | nightly（把 X11 画面渲染到 Android Surface） |
| XFCE | 4.20（xfwm4 + xfce4-panel + thunar + xfce4-terminal） |
| 占用 | `$PREFIX` 约 **1.3GB** |
| 软件源 | 清华镜像（官方源在手机上仅 ~130KB/s） |

桌面能力：**鼠标拖标题栏移动、拖边缘缩放、双击最大化、右键菜单、任务栏、Alt+Tab、多工作区** —— 这才是"PC 样式"。

## 6. 关键坑（每条都踩过，含现象/原因/处理）

### 6.1 投屏窗口只占屏幕 1/4
- **现象**：窗口看着"全屏"，实际只填满左上角。
- **原因**：`--window-width/--window-height` 是**物理像素**。PC 是 2880×1800 物理 / 200% 缩放，填 1440×900（逻辑尺寸）只等于 1/4 屏。
- **处理**：填 **2880×1800**（真实物理像素）。

### 6.2 以为"已经满屏"的假象
- **现象**：截图里明明铺满。
- **原因**：PowerShell 默认 **DPI-unaware**，`CopyFromScreen(0,0,1440,900)` 只截到左上角 1440×900 物理像素 —— 正好等于那个 1/4 窗口，看起来就是整屏。
- **处理**：截图/量窗口前先 `SetProcessDpiAwarenessContext(-4)`，再按 2880×1800 截。

### 6.3 `Alt+F` / `--fullscreen` 画面被放大裁切
- **原因**：scrcpy 5.0.1 在 200% 缩放下的 HiDPI bug，全屏时按 2 倍渲染并裁边。
- **处理**：**不要按 Alt+F**，用 `--window-borderless + 物理尺寸` 代替全屏。

### 6.4 空虚拟屏会被回收
- **现象**：`--new-display` 后窗口一闪，屏没了。
- **处理**：一定带 `--start-app=包名`；`2-start-pc.bat` 内已固定。

### 6.5 freeform 小窗的硬限制
- **现象**：`am task resize` 写 1600×1000 成功（dumpsys 显示正确），窗口实际只长到 ~70%；没有标题栏，鼠标拖不动。
- **原因**：系统未开 `enable_freeform_support` 时，MIUI 只给"隐式 freeform"，窗口管理能力缺失；拖动把手只认触摸长按。
- **处理**：多窗口用 `4-windows.bat` 平铺/最大化；要真桌面走层二。

### 6.6 Taskbar 抢默认桌面 → 清后台卡屏/黑屏
- **现象**：清完后台回桌面黑屏、卡顿、闪烁。
- **原因**：Taskbar 把自己注册成默认 HOME（`HSLActivity`），在手机主屏上等于一个空桌面。
- **处理**：`cmd package set-home-activity com.miui.home/.launcher.Launcher` + `am force-stop com.farmerbb.taskbar`；`2-start-pc.bat` 不再启动 Taskbar。

### 6.7 硬杀 scrcpy → 残留 server + 孤儿虚拟屏 → UI 闪烁
- **现象**：手机掉帧、闪烁。
- **原因**：直接 `taskkill` 只杀 PC 端，手机里留下 `app_process`（scrcpy server）和一块 displayId≠0 的孤儿屏，系统持续多合成。
- **处理**：用 `stop-pc.bat`（`pkill -f com.genymobile.scrcpy`），它会校验只剩 displayId 0。

### 6.8 权限：两个开关分工不同
| 开关 | 控制什么 |
|---|---|
| 开发者选项 →「USB 安装」 | `adb install`（装 APK） |
| 开发者选项 →「USB 调试（安全设置）」 | `settings put` / `wm size` / `input` 注入 / `INJECT_EVENTS` —— **本方案不需要它** |

### 6.9 这台 PC 的 `%TEMP%` 坏了
- **现象**：`adb: cannot open ...\Temp\adb.log: Permission denied`。
- **处理**：所有 .bat 开头把 `TEMP/TMP` 指向 `pc-mode\tmp\`；ps1 里同样设置。

### 6.10 编码：批处理与脚本
- `.bat`：**CRLF + ASCII**（cmd 对 LF/UTF-8 会错位吞命令）
- `.ps1`：**UTF-8 with BOM**（PowerShell 5.1 否则按 ANSI 读，中文注释会炸掉语法）
- 手机侧 `.sh`：LF 即可

### 6.11 怎么从 PC 驱动 Termux（没有输入注入权限）
- Termux 装的是 **debug 构建** → `adb shell run-as com.termux <cmd>` 可用（普通构建不行）
- 传脚本：`base64` 编码后用 `base64 -d` 写进 `files/home/`（`/sdcard` 无权访问，`pm grant` 存储权限被 MIUI 拒）
- 长驻进程：`setsid ... nohup ... </dev/null &`，否则 adb shell 退出就被杀
- **注意**：PowerShell 双引号里 `$HOME` 会被本机展开，必须用单引号 here-string

### 6.12 Termux 里启动不了安卓 App
- **现象**：`/system/bin/am start` 报 `SecurityException: package=com.android.shell does not belong to uid=10298`
- **原因**：`am` 冒充 shell 身份，普通应用无权
- **现状**：只能由 PC 侧 adb 启动（`2-app-full.bat`）；要桌面图标启动，需在 Termux 里配 adb 无线调试配对

### 6.13 Termux:X11 的额外按键条/导航栏
- **处理**：写 `shared_prefs/com.termux.x11_preferences.xml`：`showAdditionalKbd=false`、`fullscreen=true`、`displayStretch=true`，然后 force-stop 重启 Activity
- 首次启动的通知授权弹窗：`am force-stop` 后重启可绕过（`pm grant` 被 MIUI 拒）

### 6.14 竖屏锁定的 App 无法铺满宽画布
- **现象**：设置/计算器/微信在 16:10 画布上居中成一条竖列（`letterBoxed=true`）
- **原因**：应用自己锁 `port`，系统只能信箱式留边
- **处理**：无解；只有横屏 App（Chrome/Edge/视频类）能真正用满宽度

## 8. 排错手册

| 症状 | 检查 | 修复 |
|---|---|---|
| 投屏窗口不见了 | `Get-Process scrcpy`；是否被浏览器盖住 | `bring-back.bat` |
| 窗口只有一小块 | 窗口尺寸是否 = 2880×1800 物理 | 改 `2-start-pc.bat` 的 `WINW/WINH` |
| 画面放大/裁切 | 是否按了 Alt+F | 别按；重开 `2-start-pc.bat` |
| 手机卡屏/闪烁 | `dumpsys display \| grep displayId` 有几块屏 | 杀掉残留 server，重启手机 |
| 桌面打不开 | `ps -A \| grep xfce`；`~/xfce.log`、`~/boot.log` | `5-xfce.bat` 重来 |
| 黑屏但进程在 | 被 Chrome 等占位 App 压住 | `to-desktop.bat` |
| adb 报 adb.log 权限 | 是否走了 `pc-mode\tmp` | 手动设 `TEMP` 再执行 |
| 脚本中文乱码/命令被吞 | 文件是否 CRLF+ASCII、UTF8 BOM | 重新规范化 |

常用排查命令：
```bat
adb -d shell "dumpsys display | grep -oE 'displayId [0-9]+' | sort -u"
adb -d shell "cmd package resolve-activity --brief -a android.intent.action.MAIN -c android.intent.category.HOME"
adb -d shell "ps -A -o PID,NAME | grep -iE 'scrcpy|xfce|termux-x11'"
adb -d shell "run-as com.termux sh -c 'tail -20 /data/data/com.termux/files/home/xfce.log'"
```

## 11. v3 增量：自适应分辨率 / 防杀后台 / 手机端按钮 / 投屏切换

### 11.1 自适应投屏尺寸（`auto-start.ps1`）

`2-start-pc.bat` 现在只做一件事：调用 `auto-start.ps1`。流程：

1. `SetProcessDpiAwarenessContext(-4)` → 拿到**真实物理分辨率**（否则是缩放后的逻辑值，会算成 1/4 屏）
2. `EnumDisplayMonitors` 枚举所有显示器（支持多屏，`-Monitor 1` 指定第 2 块）
3. **虚拟屏尺寸 = 显示器原生分辨率**，密度按 `160 × 宽 / 1163` 反算（保持 ~1163dp 桌面宽）
4. 窗口坐标/尺寸 = 该显示器的物理矩形 → 无边框铺满

实测（单屏 2880×1800）：`虚拟屏 2880x1800/396dpi（=1164x727dp）`，窗口 2880×1800 @ (0,0)。
换成 1080p 显示器会自动变成 `1920x1080/264dpi`，4K 变 `3840x2160/528dpi`，不需要改任何参数。

### 11.2 防杀后台（已生效）

| 手段 | 命令 |
|---|---|
| Doze 白名单 | `dumpsys deviceidle whitelist +com.termux` / `+com.termux.x11` |
| 活跃待机桶 | `am set-standby-bucket com.termux active`（实测返回 bucket=5 ACTIVE） |
| 后台运行权限 | `cmd appops set com.termux RUN_IN_BACKGROUND allow` |
| Termux 唤醒锁 | 启动脚本里 `termux-wake-lock`，停止时 `termux-wake-unlock` |

> MIUI 自己的"后台白名单"在设置里，adb 改不了；上面这些已经把系统层面的回收挡住大半。

### 11.3 手机端按钮（Termux:Widget）

装了 `com.termux.widget`，并在 Termux 里放了三个快捷脚本：

```
~/.shortcuts/1-开Linux.sh    启动 termux-x11 + XFCE，同时拿唤醒锁
~/.shortcuts/2-停Linux.sh    杀掉桌面进程，释放唤醒锁
~/.shortcuts/3-状态.sh       看进程/屏幕/白名单状态
```

**添加方式**：长按桌面空白 → 小部件（卡片）→ 找 "Termux:Widget" → 拖到桌面 → 出现三个按钮。

同时已开 `~/.termux/termux.properties` 的 `allow-external-apps=true`（RUN_COMMAND 必需）。

**能力边界（重要）**：Termux 是普通 App，`am start` 会被系统拒绝
（`SecurityException: package=com.android.shell does not belong to uid=10298`），所以：

- ✅ 手机端能做：**在后台把 Linux 拉起来 + 保活**（PC 一连上，桌面已经在跑）
- ❌ 手机端不能做：把画面切到虚拟屏、显示到屏幕（这必须由 PC 端 `to-desktop.bat` 或用户点 Termux:X11 图标完成）

### 11.4 投屏切换（`switch.bat`）

一个菜单搞定三种显示：

```
1 = Linux 桌面 (start-xfce.ps1 -Attach)
2 = 指定安卓 App（输入包名 → open-app.ps1 全屏）
3 = 手机本机屏幕镜像（重启 scrcpy，不带 --new-display）
```

`-Attach` 会先 `force-stop com.android.chrome`（占位 App），否则它会压在新开的桌面上。

## 12. v4：退役「PC 风格层」+ 环境检测/自动安装

### 12.1 退役清单

定位改成「Linux 当主机 + 安卓当备用」，安卓那套桌面化外壳全部退场：

| 处理 | 对象 |
|---|---|
| **卸载** | `com.farmerbb.taskbar`（PC 风格桌面壳，曾抢默认 HOME 导致卡屏） |
| **归档到 `_pc-style-deprecated/`** | `1-enable-freeform.bat`、`3-rollback.bat`、`4-windows.bat`、`pc-win.ps1`、Taskbar apk、`dl-taskbar.js` |
| **保留** | `Termux:Widget`（手机端「开 Linux」按钮，不属于 PC 化）、`open-app.ps1` / `2-app-full.bat`（偶尔要看安卓 App） |

### 12.2 投屏到底靠什么

**一根数据线就够，手机端不需要装任何投屏 App。**

scrcpy 每次运行时会临时把 `scrcpy-server.jar` 推到手机、用 `app_process` 跑起来，退出即销毁。所以：
- 需要：数据线 + 手机开「USB 调试」
- 不需要：任何投屏类 App、root、同一 WiFi
- 我们用的是 USB 2.0（480Mbps），40Mbps 码率完全跑得动
- 无线也行（`adb tcpip` / 无线调试），但带宽和延迟都更差，画质要降

### 12.3 环境检测 / 自动安装（新增）

| 命令 | 作用 |
|---|---|
| `check.bat` | 只读检测 14 项：scrcpy、USB、机型、显示器物理分辨率、Termux/Termux:X11/Widget、run-as、XFCE、termux-x11、openssh、Doze 白名单、待机桶、当前屏幕、桌面进程 |

## 13. v5：守护进程（模式仲裁 / 温度调度 / 通知回传 / 开机自启）+ 图形启动器

手机侧脚本在 `phone/` 目录，实际部署到 Termux 家目录：

| 文件 | 部署位置 | 作用 |
|---|---|---|
| `host-mode.sh` | `~/host-mode.sh` | 模式仲裁 + 电量/温度联动（常驻，20s 轮询） |
| `notify-bridge.sh` | `~/notify-bridge.sh` | 安卓通知 → XFCE 桌面（25s 轮询，hash 去重） |
| `start-host.sh` | `~/.termux/boot/start-host.sh` | 开机自启（Termux:Boot 调用） |

### 13.1 模式仲裁

数据源是 `termux-battery-status`（JSON）。**不能用 `/sys/class/power_supply`**：Termux 是普通 App，SELinux 不让读。

| 条件 | 动作 |
|---|---|
| `plugged != PLUGGED_UNPLUGGED` | **主机模式**：起 termux-x11 + XFCE，`termux-wake-lock` |
| 拔电 | **手机模式**：杀桌面进程，`termux-wake-unlock`（省电） |

### 13.2 电量/温度联动

| 温度 | 动作 |
|---|---|
| ≥ 60°C | 桌面进程 `renice 19`（不抢前台 CPU） |
| ≥ 72°C | 停桌面保护手机 + 弹通知 |
| < 45°C | 恢复优先级，必要时重新进主机模式 |

实测日志：`2026-10-31 19:08:47 → 主机模式：桌面已启动，唤醒锁 ON`（插电状态）。

### 13.3 通知回传

`termux-notification-list | jq` 取 title/content → `DISPLAY=:0 notify-send`，用 md5 存 `~/.notif-seen` 去重。

⚠️ **需要手动授权一次**：设置 → 通知与状态栏 → 通知使用权 → 允许「Termux:API」。
（`settings put secure enabled_notification_listeners` 需要「USB 调试（安全设置）」，没开就写不进去。）
另外脚本里给 `termux-notification-list` 加了 `timeout 15`，未授权时不会把桥接卡死。

### 13.4 开机自启

装 `Termux:Boot`（`com.termux.boot`），脚本放 `~/.termux/boot/`。开机时它会拉起 host-mode + notify-bridge（sshd 若已配置 key 也会拉）。
验证方式：重启手机后 `cat ~/boot.log`。

### 13.5 图形启动器（Windows 侧）

双击 **`启动.bat`** 打开「手机主机 · PC 启动器」：

- 顶部实时状态：机型 / 电量 / 温度 / 电源 / 模式（主机 or 手机）/ 屏幕列表，15s 自动刷新
- 9 个按钮：环境检测、开画布、开 Linux 桌面、切回桌面、切到安卓 App、手机屏幕镜像、一键补齐环境、收工、刷新状态
- 投屏设置：码率（20/40/60/80M）、帧率（30~120）、起始 App 包名，保存到 `launcher.json`
- **界面缩放**：70%（默认）/ 80% / 85% / 100% / 115%，选完点「应用」自动重启界面；当前 70% 时窗口约 490×543 逻辑像素（物理 980×1087）
- 底部日志框实时显示每个动作的输出

## 14. 黑屏问题：清后台把「画布上的那层壳」杀了

### 现象
PC 上投屏窗口在手机「清理后台」后变全黑。

### 诊断（实测）
清理后台后检查进程，发现：

```
xfce4-session        还在跑
termux-x11 :0 -ac    还在跑（X 服务器）
dbus-launch          还在跑
```

**死的只有 `com.termux.x11` 这个 Android App** —— 它是把 X11 画面渲染到 Android Surface 上的那层壳。
虚拟屏上没了这个任务，自然就是黑的。所以这不是崩溃，是「画布还在，画笔被收走了」。

更麻烦的是：**只重新挂上 App 不够**。实测 `am force-stop com.termux.x11` 后再 `-Attach`，
App 是回到了前台（`topResumedActivity=com.termux.x11/.MainActivity`），但画面依旧全黑 ——
因为它和 X 服务器的连接已经断了，必须把 X 服务器一起重启。

### 修复

| 措施 | 说明 |
|---|---|
| 启动器内置自动恢复 | 每 15s 检查前台是不是 `com.termux.x11`，不是就**整窗重启桌面**（60s 冷却防抖） |
| 给 `com.termux.x11` 加后台保护 | `RUN_IN_BACKGROUND` / `RUN_ANY_IN_BACKGROUND` / standby bucket=active / Doze 白名单 |
| 手动救急 | `5-xfce.bat`（完整重启，约 10s）/ `to-desktop.bat`（只重新挂，能救的情况 2s） |

### 从根上减少复发（MIUI 手动设置，各一次）

1. 设置 → 应用设置 → 应用管理 → **Termux:X11** → 省电策略 → **无限制**
2. 同页 → **自启动** → 允许
3. 最近任务里把 **Termux:X11** 的卡片**下拉锁定**（出现锁图标）

`Termux` 本体也要做同样三步 —— 如果被杀的是 Termux，`host-mode` 守护也会一起消失，那就不会自动恢复了。

## 15. 加固后台存活（adb 能改的全拉满）

### 15.1 查出来的问题

`appops get` 对比两个包：

| 包 | WAKE_LOCK | START_FOREGROUND | RUN_IN_BACKGROUND |
|---|---|---|---|
| `com.termux` | allow（running） | allow（running） | allow |
| `com.termux.x11` | **缺省（没有条目）** | **缺省** | allow |

也就是说 X11 那个"壳"从来没被显式授予前两项，属于随时可被回收的状态。

### 15.2 已施加（`harden.bat` / `harden.ps1`）

对 `com.termux` / `com.termux.x11` / `com.termux.api` / `com.termux.boot` / `com.termux.widget` 五个包统一执行：

```bat
cmd appops set <pkg> WAKE_LOCK allow
cmd appops set <pkg> START_FOREGROUND allow
cmd appops set <pkg> RUN_IN_BACKGROUND allow
cmd appops set <pkg> RUN_ANY_IN_BACKGROUND allow
am set-inactive <pkg> false
am set-standby-bucket <pkg> active
dumpsys deviceidle whitelist +<pkg>
```

验证输出：`termux bucket=5 (ACTIVE) whitelist=5 appops命中=2`、`termux.x11 bucket=5 whitelist=1 appops命中=2`。

`setup.bat`（provision）末尾也会自动跑一遍。

### 15.3 自动恢复升级：像素级黑屏检测

之前只判断"前台是不是 Termux:X11"，但黑屏那种情况 App 明明在前台却一片黑，判断不出来。
现在启动器 `Try-Recover` 增加了**取投屏窗口中心 80×80 像素算平均值**，`< 12` 判定为黑屏 → 整窗重启桌面（60s 冷却）。

实测复现与自愈：

```
1. am force-stop com.termux.x11        ← 模拟清理
2. start-xfce.ps1 -Attach              ← 只挂回去 → 黑屏（复现成功）
3. 等 ~20s                             ← 启动器检测到黑屏
4. XFCE / termux-x11 的 PID 全部变化    ← 说明做了完整重启
5. 画面恢复                            ← 自愈成功
```

### 15.4 仍然改不了的

`pm disable-user <pkg>/<activity>`（隐藏图标）和 `settings put secure enabled_notification_listeners` 都一样被 MIUI 拒绝。
MIUI 的**省电策略 / 自启动 / 最近任务锁定**存在它自己的库里，没有 root 写不进去，只能手点。

## 16. 镜像窗口的两种形态（v6）

| 入口 | 形态 | 适用 |
|---|---|---|
| `mirror-window.bat` | **带标题栏的普通窗口**：鼠标拖标题栏移动、拖边缘缩放；默认占屏幕高度 74%，按当前屏幕方向算宽高比（`dumpsys display` 里的 `mRotation`） | 边看手机边干别的 |
| `mirror-touch.bat` | **无边框全屏**：窗口铺满显示器，视频按比例缩放居中，多出来的地方留黑边（不裁切、不拉伸） | 专心操作手机 |

两者都用 `--mouse=sdk`（真触摸注入，需要「USB 调试（安全设置）」，已开）。

实现要点：`mirror-phone.ps1 -Mode window|full`；宽高比不能直接用 `wm size`（永远是竖屏基准），要看当前 `mRotation` 再决定是 `w/h` 还是 `h/w`。
